THERAPY APPOINTMENT SUMMARY APPLICATION
DEPLOYMENT ENVIRONMENT VARIABLES REFERENCE INFO

================================================================================
1. DATABASE VARIABLES
================================================================================
These define the connection parameters to your MySQL database. When deploying to
production, replace these with values from your cloud database provider.

DB_HOST
  - Description: Domain name or IP address of the MySQL server.
  - Examples:
      Local: localhost (or 127.0.0.1)
      Production (FreeDB): sql.freedb.tech

DB_PORT
  - Description: Port number where MySQL is listening.
  - Examples: 3306 (default MySQL port)

DB_USER
  - Description: Username used to log in to the database.
  - Examples:
      Local: root
      Production (FreeDB): u_RDjna4

DB_PASSWORD
  - Description: Password associated with the DB_USER account.
  - Examples:
      Local: [your_local_mysql_password]
      Production (FreeDB): [your_freedb_password]

DB_NAME
  - Description: The specific database schema name.
  - Examples:
      Local: therapy_summary_db
      Production (FreeDB): freedb_S9DTfxfl

================================================================================
2. EXTERNAL SERVICES & API KEYS
================================================================================
OPENROUTER_API_KEY
  - Description: The API authorization token used to connect to OpenRouter.
  - Purpose: Generates AI summaries of therapy session notes using GPT-4o-mini.
  - Values: Format starts with 'sk-or-v1-...'

================================================================================
3. APPLICATION PLATFORM CONFIGURATIONS
================================================================================
PORT
  - Description: The local network port the Express server listens to.
  - Value: Typically 5000 in local development. In cloud deployments (e.g. Render,
           Railway, Heroku), leave this empty; the host will assign it dynamically.

NODE_ENV
  - Description: Sets the running mode of the Node runtime.
  - Values:
      development: Enables hot-reloading (nodemon) and full debug stack traces.
      production: Optimizes runtime performance, suppresses verbose developer logs,
                  and hides detailed error stack traces from end-users.

================================================================================
DEPLOYMENT BEST PRACTICES
================================================================================
1. Keep .env out of Git: Ensure server/.env is listed in your .gitignore file to
   prevent your API keys and database passwords from being exposed on GitHub.
2. Dashboards: Use your hosting provider's dashboard (e.g., Render, AWS, Railway)
   to define these keys as environment variables rather than uploading a .env file.
